# Nexus Messaging

Nexus Messaging, conversations, communities, stories, and video sharing into a single Expo mobile experience.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)

## Where things live

- `artifacts/nexus-app/` — Expo Router mobile application
- `artifacts/api-server/` — Express and Socket.IO API
- `lib/db/src/schema/` — Drizzle database schema
- `lib/api-spec/openapi.yaml` — API contract source of truth
- `.github/workflows/build-android.yml` — signed APK and GitHub Release automation
- `README.md` — full setup, signing, and release documentation

## Architecture decisions

- Native Android folders are generated by Expo prebuild in CI rather than committed.
- The mobile client accepts `EXPO_PUBLIC_API_URL` so GitHub-built APKs never need to use localhost.
- Release APKs use an automatically generated key when persistent signing secrets are not configured; persistent GitHub Secrets are recommended for upgrade-compatible releases.
- `expo.version` is the product version while the GitHub Actions run number becomes the Android `versionCode`.

## Product

Nexus supports direct messages, groups, channels, stories, video feed, user profiles,
notifications, media upload, search, reactions, and a dedicated About Nexus feature
overview.

## User preferences

- Keep release credentials out of source control and chat.
- Prefer explicit build failures over publishing an APK with an invalid API endpoint.

## Gotchas

- A GitHub Actions build requires the `NEXUS_API_URL` repository variable or a manual `api_url` input.
- Reusing the same signing identity requires all four `NEXUS_KEY*` secrets; auto-generated fallback keys are per-release.
- Run `pnpm --filter @workspace/api-spec run codegen` after OpenAPI changes.
